> **Where this fits now:** BizFlip is the case study that became the [Websites & Internal Tools](/services#web-tools) offer. The service is the same work — a focused rebuild for a local business — packaged for a client instead of presented as a demo. Keeping it here is honest: it is where the offer came from.

## The problem

Local businesses often have a site that was fine in 2010 and is now actively costing them customers: fixed-width layout, no mobile tap-to-call, a menu trapped in an image, and a visitor counter.

The interesting constraint was time. A small business does not want a six-week discovery process for a five-page site. Can a weekend produce something genuinely better, not just newer?

## What I built

A complete rebuild in 48 hours, packaged as a case study with the old version and the new one both runnable:

- **Mobile-first layout** with tap-to-call and a sticky order action.
- **Real menu structure** with prices and hours as text, not a photographed chalkboard.
- **Local SEO basics**: title and meta description written for the neighborhood, structured data for a restaurant, and a clean heading hierarchy.
- **Performance discipline**: system fonts, compressed images, no framework for a five-section page, and a Lighthouse pass that reflects that.
- **A before/after viewer** that loads the dated original on purpose, because "trust me, it was bad" is weaker than showing it.

## The decisions that mattered

The rebuild keeps the taquería's identity — the same name, the same food, the same voice — and changes only the delivery. That is the actual service for a local business: not a new brand, a working front door.

I also resisted a CMS. For a menu that changes twice a year, a static page with a documented edit path is faster, cheaper, and harder to break than a WordPress install someone has to maintain.

## What I learned

Speed is a design constraint, not a compromise. Working in 48 hours forced decisions: one typeface, one accent color, one clear action per screen. The result is tighter than most open-ended builds I have done.

## Honest limits

This is a demonstration case, not a live client engagement. The performance and accessibility work is real; the traffic and revenue claims that usually accompany a case study like this are deliberately absent.
